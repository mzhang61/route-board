## Hard gates

1. Secrets: local credentials stay ignored/server-side. Current local, remote-history, recent CI, deployed API/web image, bounded Azure runtime, database-log, and media scans are linked above. Every pattern match in the reviewed inputs was classified as a public hash/revision/digest or certificate fingerprint; database logs and media had zero matches. Scans are pattern-based and bounded to the stated sources/windows. Review the actual submission bundle and keep live credentials out of screenshots, logs, and the browser bundle.
2. Evidence: Local and deployed results are labeled by environment. Earlier failed runs are retained honestly.
3. Reproducibility: A fresh public clone followed the README with isolated package caches and a new database volume; deployment instructions and Azure environments are recorded. The rehearsal used an existing Mac with tools installed and cached Docker image layers.
4. Authorization: public endpoints are reads; REST writes and every MCP tool enforce permissions. Tests cover representative denials. Staging and production used Auth0 for the recorded role checks.
5. Synthetic data: demo/test operational data and simulated positions are fictional; authentication retains only issuer/subject for attribution.
